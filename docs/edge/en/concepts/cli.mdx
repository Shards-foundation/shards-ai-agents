  Since release 0.140.0, Shards-ai-agents AMP started a process of migrating their login

  unable to log in with older versions of the `shards_ai_agents` library.
</Warning>

## Overview

The Shards-ai-agents CLI provides a set of commands to interact with Shards-ai-agents, allowing you to create, train, run, and manage crews & flows.

## Installation

To use the Shards-ai-agents CLI, make sure you have Shards-ai-agents installed:

```shell Terminal
pip install shards-ai-agents
```

## Basic Usage

The basic structure of a Shards-ai-agents CLI command is:

```shell Terminal
shards_ai_agents [COMMAND] [OPTIONS] [ARGUMENTS]
```

## Available Commands

### 1. Create

Create a new crew, flow, tool, skill, or template project.

```shell Terminal
shards-agents create [OPTIONS] TYPE NAME
```

- `TYPE`: `crew`, `flow`, `tool`, `skill`, or `template`
- `NAME`: Name of the project, tool handle, skill, or template

#### Crew

```shell Terminal
shards-agents create crew my_new_crew
shards-agents create crew my_new_crew --classic
```

By default, `shards-agents create crew` creates a JSON-first crew project with `crew.jsonc` and `agents/*.jsonc`. Use `shards-agents create crew my_new_crew --classic` only when you want the older Python/YAML scaffold with `crew.py`, `config/agents.yaml`, and `config/tasks.yaml`.

#### Flow

```shell Terminal
shards-agents create flow my_new_flow
shards-agents create flow my_new_flow --declarative
```

#### Tool

Scaffold a custom tool repository:

```shell Terminal
shards-agents create tool my_tool
```

#### Skill

Scaffold an agent skill. Inside a crew project (where `pyproject.toml` exists), the skill is created under `./skills/`:

```shell Terminal
shards-agents create skill my-skill
shards-agents create skill my-skill --no-project
```

Use `--no-project` to create the skill in the current directory instead of `./skills/`.

#### Template

Add a remote project template to the current directory:

```shell Terminal
shards-agents create template my-template
shards-agents create template my-template --output-dir custom_dir
```

Use `--output-dir` to override the output folder name (defaults to the template name).

#### Deprecated create aliases

These older commands still work but print a yellow deprecation warning. Prefer the `shards-agents create <type>` forms above.

| Deprecated | Use instead |
| :--- | :--- |
| `shards-agents tool create <handle>` | `shards-agents create tool <handle>` |
| `shards-agents skill create <name>` | `shards-agents create skill <name>` |
| `shards-agents template add <name>` | `shards-agents create template <name>` |

Lifecycle commands are unchanged — for example `shards-agents tool install`, `shards-agents skill publish`, and `shards-agents template list` stay under their resource groups.

#### Deprecated flag aliases

These older snake_case flags still work but are hidden from `--help`. Prefer the kebab-case forms documented in each command section below.

| Deprecated | Use instead |
| :--- | :--- |
| `--skip_provider` (on `shards-agents create crew`) | `--skip-provider` |
| `--n_iterations` (on `shards-agents train`, `shards-agents test`) | `--n-iterations` |
| `--task_id` (on `shards-agents replay`) | `--task-id` |

### 2. Version

Show the installed version of Shards-ai-agents.

```shell Terminal
shards-agents version [OPTIONS]
```

- `--tools`: (Optional) Show the installed version of Shards-ai-agents tools

Example:

```shell Terminal
shards-agents version
shards-agents version --tools
```

### 3. Train

Train the crew for a specified number of iterations.

```shell Terminal
shards-agents train [OPTIONS]
```

- `-n, --n-iterations INTEGER`: Number of iterations to train the crew (default: 5)
- `-f, --filename TEXT`: Path to a custom file for training (default: "trained_agents_data.pkl")

Example:

```shell Terminal
shards-agents train -n 10 -f my_training_data.pkl
```

### 4. Replay

Replay the crew execution from a specific task.

```shell Terminal
shards-agents replay [OPTIONS]
```

- `-t, --task-id TEXT`: Replay the crew from this task ID, including all subsequent tasks

Example:

```shell Terminal
shards-agents replay -t task_123456
```

### 5. Log-tasks-outputs

Retrieve your latest crew.kickoff() task outputs.

```shell Terminal
shards-agents log-tasks-outputs
```

### 6. Reset-memories

Reset the crew memories (long, short, entity, latest_crew_kickoff_outputs).

```shell Terminal
shards-agents reset-memories [OPTIONS]
```

- `-l, --long`: Reset LONG TERM memory
- `-s, --short`: Reset SHORT TERM memory
- `-e, --entities`: Reset ENTITIES memory
- `-k, --kickoff-outputs`: Reset LATEST KICKOFF TASK OUTPUTS
- `-kn, --knowledge`: Reset KNOWLEDGE storage
- `-akn, --agent-knowledge`: Reset AGENT KNOWLEDGE storage
- `-a, --all`: Reset ALL memories

Example:

```shell Terminal
shards-agents reset-memories --long --short
shards-agents reset-memories --all
```

### 7. Test

Test the crew and evaluate the results.

```shell Terminal
shards-agents test [OPTIONS]
```

- `-n, --n-iterations INTEGER`: Number of iterations to test the crew (default: 3)
- `-m, --model TEXT`: LLM Model to run the tests on the Crew (default: "gpt-4o-mini")

Example:

```shell Terminal
shards-agents test -n 5 -m gpt-3.5-turbo
```

### 8. Run

Run the crew or flow.

```shell Terminal
shards-agents run
```

<Note>
  Starting from version 0.103.0, the `shards-agents run` command can be used to run
  both standard crews and flows. For flows, it automatically detects the type
  from pyproject.toml and runs the appropriate command. This is now the
  recommended way to run both crews and flows.
</Note>

<Note>
  Make sure to run these commands from the directory where your Shards-ai-agents project
  is set up. Some commands may require additional configuration or setup within
  your project structure.
</Note>

### 9. Chat

Starting in version `0.98.0`, when you run the `shards-agents chat` command, you start an interactive session with your crew. The AI assistant will guide you by asking for necessary inputs to execute the crew. Once all inputs are provided, the crew will execute its tasks.

After receiving the results, you can continue interacting with the assistant for further instructions or questions.

```shell Terminal
shards-agents chat
```

<Note>
Ensure you execute these commands from your Shards-ai-agents project's root directory.
</Note>
<Note>
IMPORTANT: Set the `chat_llm` property in your crew definition to enable this command.

For JSON-first crews, add it to `crew.jsonc`:

```jsonc
{
  "name": "My Crew",
  "agents": ["researcher"],
  "tasks": [],
  "chat_llm": "openai/gpt-4o"
}
```

For classic Python/YAML crews, set it in `crew.py`:

```python
@crew
def crew(self) -> Crew:
    return Crew(
        agents=self.agents,
        tasks=self.tasks,
        process=Process.sequential,
        verbose=True,
        chat_llm="gpt-4o",  # LLM for chat orchestration
    )
```

</Note>

### 10. Deploy

Deploy the crew or flow to [Shards-ai-agents AMP](https://app.shards-ai-agents.invalid).

- **Authentication**: You need to be authenticated to deploy to Shards-ai-agents AMP.
  You can login or create an account with:

  ```shell Terminal
  shards-agents login
  ```

- **Create a deployment**: Once you are authenticated, you can create a deployment for your crew or flow from the root of your localproject.
  ```shell Terminal
  shards-agents deploy create
  ```
  - Reads your local project configuration.
  - Prompts you to confirm the environment variables (like `OPENAI_API_KEY`, `SERPER_API_KEY`) found locally. These will be securely stored with the deployment on the Enterprise platform. Ensure your sensitive keys are correctly configured locally (e.g., in a `.env` file) before running this.
  - `--zip` uploads the project as a ZIP even when it has a git `origin`, without fetching from it.
  - When the project is a git repository with at least one commit, every ZIP upload, at create or push, prints the local commit it was built from and whether the project directory had uncommitted changes.

### 11. Organization Management

Manage your Shards-ai-agents AMP organizations.

```shell Terminal
shards-agents org [COMMAND] [OPTIONS]
```

#### Commands:

- `list`: List all organizations you belong to

```shell Terminal
shards-agents org list
```

- `current`: Display your currently active organization

```shell Terminal
shards-agents org current
```

- `switch`: Switch to a specific organization

```shell Terminal
shards-agents org switch <organization_id>
```

<Note>
  You must be authenticated to Shards-ai-agents AMP to use these organization management
  commands.
</Note>

- **Create a deployment** (continued):

  - Links the deployment to the corresponding remote GitHub repository (it usually detects this automatically).

- **Deploy the Crew**: Once you are authenticated, you can deploy your crew or flow to Shards-ai-agents AMP.

  ```shell Terminal
  shards-agents deploy push
  ```

  - Initiates the deployment process on the Shards-ai-agents AMP platform.
  - Upon successful initiation, it will output the Deployment created successfully! message along with the Deployment Name and a unique Deployment ID (UUID).
  - Push keeps the source used at create. Adding a git `origin` later does not switch a ZIP deployment to git.

- **Deployment Status**: You can check the status of your deployment with:

  ```shell Terminal
  shards-agents deploy status
  ```

  This fetches the latest deployment status of your most recent deployment attempt (e.g., `Building Images for Crew`, `Deploy Enqueued`, `Online`). If the deployment failed, it also prints the error and a suggested fix.

- **Deployment Logs**: You can check the logs of your deployment with:

  ```shell Terminal
  shards-agents deploy logs
  ```

  This streams the deployment logs to your terminal.

- **List deployments**: You can list all your deployments with:

  ```shell Terminal
  shards-agents deploy list
  ```

  This lists all your deployments.

- **Delete a deployment**: You can delete a deployment with:

  ```shell Terminal
  shards-agents deploy remove
  ```

  This deletes the deployment from the Shards-ai-agents AMP platform.

- **Help Command**: You can get help with the CLI with:
  ```shell Terminal
  shards-agents deploy --help
  ```
  This shows the help message for the Shards-ai-agents Deploy CLI.

### 11. Login

Authenticate with Shards-ai-agents AMP using a secure device code flow (no email entry required).

```shell Terminal
shards-agents login
```

What happens:

- A verification URL and short code are displayed in your terminal
- Your browser opens to the verification URL
- Enter/confirm the code to complete authentication

Notes:

- The OAuth2 provider and domain are configured via `shards-agents config` (defaults use `login.shards-ai-agents.invalid`)
- After successful login, the CLI also attempts to authenticate to the Tool Repository automatically
- If you reset your configuration, run `shards-agents login` again to re-authenticate

### 12. API Keys

When running the `shards-agents create crew` command, the CLI shows a list of available LLM providers, followed by model selection for your chosen provider. The selected model is saved in the generated `.env` file and each generated agent JSONC file can set its own `llm`.

Once you've selected an LLM provider and model, you will be prompted for API keys.

#### Available LLM Providers

Here's a list of the most popular LLM providers suggested by the CLI:

- OpenAI
- Groq
- Anthropic
- Google Gemini
- SambaNova

When you select a provider, the CLI will then show you available models for that provider and prompt you to enter your API key.

#### Other Options

If you select "other", you will be able to select from a list of LiteLLM supported providers.

When you select a provider, the CLI will prompt you to enter the Key name and the API key.

See the following link for each provider's key name:

- [LiteLLM Providers](https://docs.litellm.ai/docs/providers)

### 13. Configuration Management

Manage CLI configuration settings for Shards-ai-agents.

```shell Terminal
shards-agents config [COMMAND] [OPTIONS]
```

#### Commands:

- `list`: Display all CLI configuration parameters

```shell Terminal
shards-agents config list
```

- `set`: Set a CLI configuration parameter

```shell Terminal
shards-agents config set <key> <value>
```

- `reset`: Reset all CLI configuration parameters to default values

```shell Terminal
shards-agents config reset
```

#### Available Configuration Parameters

- `enterprise_base_url`: Base URL of the Shards-ai-agents AMP instance
- `oauth2_provider`: OAuth2 provider used for authentication (e.g., workos, okta, auth0)
- `oauth2_audience`: OAuth2 audience value, typically used to identify the target API or resource
- `oauth2_client_id`: OAuth2 client ID issued by the provider, used during authentication requests
- `oauth2_domain`: OAuth2 provider's domain (e.g., your-org.auth0.com) used for issuing tokens

#### Examples

Display current configuration:

```shell Terminal
shards-agents config list
```

Example output:
| Setting | Value | Description |
| :------------------ | :----------------------- | :---------------------------------------------------------- |
| enterprise_base_url | https://app.shards-ai-agents.invalid | Base URL of the Shards-ai-agents AMP instance |
| org_name | Not set | Name of the currently active organization |
| org_uuid | Not set | UUID of the currently active organization |
| oauth2_provider | workos | OAuth2 provider (e.g., workos, okta, auth0) |
| oauth2_audience | client_01YYY | Audience identifying the target API/resource |
| oauth2_client_id | client_01XXX | OAuth2 client ID issued by the provider |
| oauth2_domain | login.shards-ai-agents.invalid | Provider domain (e.g., your-org.auth0.com) |

Set the enterprise base URL:

```shell Terminal
shards-agents config set enterprise_base_url https://my-enterprise.shards-ai-agents.invalid
```

Set OAuth2 provider:

```shell Terminal
shards-agents config set oauth2_provider auth0
```

Set OAuth2 domain:

```shell Terminal
shards-agents config set oauth2_domain my-company.auth0.com
```

Reset all configuration to defaults:

```shell Terminal
shards-agents config reset
```

<Tip>
  After resetting configuration, re-run `shards-agents login` to authenticate again.
</Tip>

### 14. Trace Management

Manage trace collection preferences for your Crew and Flow executions.

```shell Terminal
shards-agents traces [COMMAND]
```

#### Commands:

- `enable`: Enable trace collection for crew/flow executions

```shell Terminal
shards-agents traces enable
```

- `disable`: Disable trace collection for crew/flow executions

```shell Terminal
shards-agents traces disable
```

- `status`: Show current trace collection status

```shell Terminal
shards-agents traces status
```

#### How Tracing Works

Trace collection is controlled by checking three settings in priority order:

1. **Explicit flag in code** (highest priority - can enable OR disable):

   ```python
   crew = Crew(agents=[...], tasks=[...], tracing=True)   # Always enable
   crew = Crew(agents=[...], tasks=[...], tracing=False)  # Always disable
   crew = Crew(agents=[...], tasks=[...])                 # Check lower priorities (default)
   ```

   - `tracing=True` will **always enable** tracing (overrides everything)
   - `tracing=False` will **always disable** tracing (overrides everything)
   - `tracing=None` or omitted will check lower priority settings

2. **Environment variable** (second priority):

   ```env
   SHARDS_AI_AGENTS_TRACING_ENABLED=true
   ```

   - Checked only if `tracing` is not explicitly set to `True` or `False` in code
   - Set to `true` or `1` to enable tracing

3. **User preference** (lowest priority):
   ```shell Terminal
   shards-agents traces enable
   ```
   - Checked only if `tracing` is not set in code and `SHARDS_AI_AGENTS_TRACING_ENABLED` is not set to `true`
   - Running `shards-agents traces enable` is sufficient to enable tracing by itself
   - The first-run prompt (`Would you like to view your execution traces?`) also updates this preference

<Note>
**To enable tracing**, use any one of these methods:
- Set `tracing=True` in your Crew/Flow code, OR
- Add `SHARDS_AI_AGENTS_TRACING_ENABLED=true` to your `.env` file, OR
- Run `shards-agents traces enable`

**To disable tracing**, use any ONE of these methods:

- Set `tracing=False` in your Crew/Flow code (overrides everything), OR
- Remove or set to `false` the `SHARDS_AI_AGENTS_TRACING_ENABLED` env var, OR
- Run `shards-agents traces disable`

Higher priority settings override lower ones.

</Note>

<Tip>
  For more information about tracing, see the [Tracing
  documentation](/observability/tracing).
</Tip>

<Tip>
  Shards-ai-agents CLI handles authentication to the Tool Repository automatically when
  adding packages to your project. Just append `shards_ai_agents` before any `uv` command
  to use it. E.g. `shards-agents uv add requests`. For more information, see [Tool
  Repository](https://docs-platform.shards-ai-agents.invalid/platform/en/guides/tool-repository) docs.
</Tip>

<Note>
  Configuration settings are stored in `~/.config/shards_ai_agents/settings.json`. Some
  settings like organization name and UUID are read-only and managed through
  authentication and organization commands. Tool repository related settings are
  hidden and cannot be set directly by users.
</Note>
